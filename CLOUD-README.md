# Онлайн-сервис «Свои» на бесплатном Cloudflare Workers

Эта конфигурация размещает чат в облаке. Компьютер создателя может быть выключен: переписка хранится в SQLite-backed Durable Object, а клиенты подключаются к общему сервису сами. Лимиты бесплатного тарифа действуют; при их превышении операции могут перестать выполняться до сброса лимита. Бесплатный тариф не даёт гарантии бесперебойной работы. Платный тариф автоматически не подключается.

**Текущий статус: код подготовлен и проверен локально. В аккаунте Cloudflare он ещё не размещён.**

## Один раз для владельца

[Развернуть в Cloudflare](https://deploy.workers.cloudflare.com/?url=https%3A%2F%2Fgithub.com%2Flogi2564%2Fimperii-online%2Ftree%2Fsvoi-release)

1. Создайте бесплатный аккаунт Cloudflare или войдите в существующий. Откройте ссылку выше и подключите свой GitHub. Развёртывание использует ветку `svoi-release`, где находится чат; в `main` сохранена прежняя игра.
2. Оставьте **Workers Free**. Если интерфейс предлагает платное обновление, остановитесь: для этой конфигурации нужен бесплатный вариант с SQLite-backed Durable Objects.
3. Для секрета `SVOI_SETUP_KEY` придумайте длинный случайный код, минимум 32 символа. Это код создателя вашей компании, а не адрес сервера. Храните его у себя; он также позволяет восстановить владельца. Не добавляйте его в Git и не отправляйте в чат.
4. Дождитесь успешного развёртывания. Cloudflare выдаст публичный HTTPS-адрес. Передайте **только этот публичный адрес** разработчику, чтобы привязать его к клиенту. Другим участникам вводить его не нужно.
5. После привязки запустите новый клиент. При первом создании компании введите своё имя, название и код создателя из шага 3. Друзьям отправляйте обычное приглашение из приложения.

Кнопка развёртывания работает через ваш аккаунт и может создать отдельный репозиторий. Исходный клиент использует общую конфигурацию `service.json` в `logi2564/imperii-online`, ветка `svoi-release`; одного создания копии в другом репозитории для подключения клиента недостаточно.

## Если развёртывание делает агент из этой среды

В настройках облачной среды подготовлены защищённые поля:

- **CLOUDFLARE_ACCOUNT_ID** — идентификатор вашего Cloudflare-аккаунта.
- **CLOUDFLARE_API_TOKEN** — секретный API-токен для вашего аккаунта. Для создания можно использовать официальный шаблон **Edit Cloudflare Workers**, ограничив его нужным аккаунтом. Прокси разрешает отправку токена только в `api.cloudflare.com`.

Не присылайте значения токенов в переписку. После сохранения этих полей агент проверяет доступ, запускает `npm run deploy`, проверяет HTTP и обмен сообщениями, затем обновляет конфигурацию клиента. Наличие полей в черновике само по себе не предоставляет доступ и не размещает сервис. Код создателя `SVOI_SETUP_KEY` задаётся как Worker secret в Cloudflare.

Для ручного развёртывания из терминала с уже подключённым Cloudflare-аккаунтом:

```sh
npm ci
npm run deploy
npx wrangler secret put SVOI_SETUP_KEY
```

Команда `secret put` читает значение интерактивно, не добавляет его в исходники. Не запускайте её с ключом в командной строке.

## Автоматическое подключение

В `service.json` хранится только публичный origin; секретов в нём нет. Пока `origin` равен `null`, клиент честно сообщает, что сервис ещё не запущен. После успешного размещения администратор выполняет:

```sh
npm run cloud:connect -- https://ИМЯ.ВАШ-ПОДДОМЕН.workers.dev
```

Скрипт проверяет `/health` и только затем сохраняет адрес. Изменение нужно отправить в ветку `svoi-release`. После этого Windows-клиент находит сервис автоматически. При недоступности GitHub он может использовать ранее проверенный адрес из своего локального кеша. Запросов адреса сервера и отдельного «локального сервера на ПК» в интерфейсе нет.

GitHub Actions проверяет оба бэкенда, собирает Worker и Windows-клиент, затем запускает переносимый EXE на Windows. При пустом `origin` публикуется предварительная EXE-сборка с явным сообщением, что переписка и звонки пока недоступны. Онлайн-релиз появляется только после проверки реально подключённого сервиса.

## Проверка и локальная разработка

```sh
npm test
npm run cloud:build
```

Тесты запускают реальный `workerd` через Miniflare и проверяют регистрацию владельца, приглашения, сообщения между двумя клиентами, реакции, права, голосовую сигнализацию и сохранение после перезапуска. Это не подтверждает успешное размещение в вашем аккаунте.

Для ручной проверки создайте **игнорируемый Git файл `.dev.vars`** с локальным тестовым `SVOI_SETUP_KEY` и запустите `npm run cloud:dev`. Чтобы настольный клиент подключался к локальному серверу разработчика, используйте переменную `SVOI_DEV_URL`, например `SVOI_DEV_URL=http://localhost:8787 npm run desktop` в Bash. Пакетная версия игнорирует эту переменную и использует общий сервис.

Durable Object использует Hibernation WebSocket API: когда никто не пишет, соединения могут оставаться открытыми без постоянной активности объекта. Присутствие и участие в голосе восстанавливаются из вложений WebSocket. Голос передаётся напрямую через WebRTC; сложные сети могут потребовать TURN, который в бесплатный хостинг этого приложения не входит.

Документация Cloudflare: [бесплатный тариф и лимиты](https://developers.cloudflare.com/durable-objects/platform/pricing/), [WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/).
