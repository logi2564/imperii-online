# DGW: Gods and Empires — 16-faction FFA expansion

This is a new playable FFA ruleset built from the user's DGW prototype for Warcraft III 1.26. It adds sixteen faction profiles, 321 object definitions, three headquarters tiers, 128 army types, sixteen champions, sixteen god avatars, 32 equipment researches, faith, five capturable shrines and two victory conditions. Native dialogs select factions in two pages; all players spawn together. Twelve independent slots replace the prototype's fixed teams and test armies. Basic computer opponents train available troops, upgrade their capital and raid.

The **Full** W3X preserves the original media quality and needs the user's large-map patch on 1.26. **Lite** has the same gameplay with six smaller opaque textures and lower-bitrate music and stays below 8 MiB. Both retain the original terrain, doodad placement, pathing and required model/UI dependencies. They have different map checksums: everyone in a match must choose the same W3X.

See [Russian player instructions](README-RU.txt) for startup, all faction names, progression, commands and verification limits. Ascend with **V at the altar**; a god's extra ability uses **Z** in an otherwise free command slot. The faction profiles share a common economic/army framework with different models, stats, prices, hero kits, some income traits and divine effects. Competitive balance and a physical twelve-player match have not been tested.

`source/catalog.json` defines all added objects and faction data. `source/globals.j`, `gameplay.j` and generated `expansion.j` are the new JASS. The original prototype's 21 trigger sources remain disabled inside the map for reference. External source files do not automatically update a W3X.

Validation reopens both actual artifacts with StormLib/War3Net, checks all packaged hashes and dependency closure, verifies classic formats and every added field, checks faction tech-tree reachability and independent forces, reconstructs the shipped script from editor metadata and compiles it against classic JASS libraries. War3Net also transpiles the actual expansion JASS to Lua for 38 controlled runtime scenarios. These tests cover selection ownership, simultaneous starts, all factions/divine casts, resource checks and one-time costs, capture contention, departures and victory transitions. Native rendering, networking, pathfinding, NewGenWE and Warcraft itself are not emulated or claimed as tested.

To rebuild after editing the catalog, use .NET 10, Python with `mpyq`, Pillow and an `ffmpeg` executable. `source/ORIGINAL.json` identifies the exact original; `source/original-assets.json` is the reviewed retained dependency list. `tools/prepare_assets.py REPO_ROOT ORIGINAL_W3X WORK_DIR STORMLIB` verifies the upload and extracts resources into a disposable build directory. Then run `tools/optimize_assets.py WORK_DIR`, `tools/make_runtime.py`, `dotnet run --project tools/Build -- ORIGINAL_W3X REPO_ROOT WORK_DIR/editor-files`, and `tools/pack_map.py WORK_DIR REPO_ROOT full` (or `lite`). Use absolute paths or run from this folder. The normal player does not need these tools. The GitHub workflow repeats the packaged-map and gameplay checks before publishing either version.
